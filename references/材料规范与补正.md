# 材料规范与补正要点

## 一、源程序鉴别材料

| 项目 | 要求 |
|---|---|
| 交存方式 | 一般交存：前 30 页 + 后 30 页，共 60 页 |
| 不足 60 页 | 全部提交，不凑数 |
| 每页行数 | **≥50 行**（末页除外） |
| 页眉 | `软件全称  版本号：V1.0`，与申请表完全一致 |
| 页码 | 右上角连续编号 |
| 纸张 | A4、纵向、单面、文字从左向右 |
| 颜色 | 黑白 |
| 注释 | 去大段注释与空行；保留必要行内注释 |
| 遮盖 | 不得大面积遮盖关键逻辑 |
| 敏感信息 | 密钥、Token、密码、内网 IP、真实用户数据用 `******` 或 `<已脱敏>` 替代 |

**取页原则**：前 30 页从主入口、核心业务模块起排；后 30 页从工具类、配置类、辅助模块倒排；前后两段尽量覆盖项目用到的主要编程语言。

## 二、软件文档鉴别材料

设计说明书与使用说明书**二选一**即可。

| 项目 | 要求 |
|---|---|
| 交存 | 前 30 页 + 后 30 页，不足 60 页全交 |
| 每页行数 | **≥30 行**（含图页可放宽） |
| 页眉 | 与源程序一致 |
| 内容 | 功能说明 + 操作流程 + 界面截图；不得只有大标题和图片 |
| 一致性 | 所述功能与代码实际模块对应 |
| 开源组件 | 标注名称、版本、许可证类型（MIT / Apache-2.0 / GPL 等） |

常规 10–30 页即可满足「不足 60 页全交」。

## 三、申请表

- 在线填报，打印的签章页不得改格式与比例
- 功能和技术特点 500–1300 字，一段话，五维度
- 经办人本人手抄承诺 + 签名 + 身份证号

## 四、证明文件

| 材料 | 适用 |
|---|---|
| 营业执照副本（加盖公章） | 单位申请 |
| 身份证正反面 | 个人申请 + 《非职务开发保证书》 |
| 委托开发合同（含归属条款） | 委托开发 |
| 合作开发协议 | 合作开发（全体著作权人协商定一名代表签章，并注明其他著作权人） |
| 任务书 / 立项文件 | 下达任务开发 |
| 原著作权人许可证明 | 在他人软件上二次开发 |
| 受让 / 继承 / 承受证明 | 继受取得 |
| 翻译机构盖章的中文译本 | 外文证明文件 |

## 五、高频补正与处置

| # | 补正原因 | 处置 |
|---|---|---|
| 1 | 某页不足 50 行 / 缺页码 / 页眉无版本号 | 调整行距字号重排，逐页点数后重新导出 |
| 2 | 页眉版本号与申请表不一致 | 全局替换，三份材料同步核对 |
| 3 | 功能描述模板化或不足 500 字 | 按五维度扩写，绑定真实模块名 |
| 4 | 签章页打印/代签/涂改/缺身份证号 | **不予受理**，只能重打重抄重签 |
| 5 | 完成日期晚于首次发表日期 | 调整完成日期，或改选未发表 |
| 6 | 软件名称含版本号/绝对化用语/纯英文 | 重新命名后全套材料重出 |
| 7 | 权属证明缺失 | 补合同、协议、任务书 |
| 8 | 说明书功能代码中找不到 | 以代码实际模块为准回写 |
| 9 | 文档每页不足 30 行 | 增补文字，图配文 |
| 10 | 上传非 PDF / 横向排版 | 全部转 PDF，纵向 |
| 11 | 错过 30 日补正期 | 视为撤回，重新申报 |
| 12 | 被认定非正常申请（短期批量、领域跨度大、材料失范） | 一次报 1–2 件，与主营业务相关，材料能自证 |

## 六、周期基准

| 节点 | 时间 |
|---|---|
| 受理 | 提交后 5–7 个工作日 |
| 审查 | 自受理日起 60 日内 |
| 补正 | 通知后 30 日内（逾期视为撤回） |
| 整体 | 约 75–90 天，高峰 3–4 个月 |
| 加急 | 经代理，3/5/10/20/30 工作日档，1000–5000 元，不豁免审查 |
